# BT REC 串流（B 方案）規格 v1.1（已實機驗證）

Stick 的麥克風經 BLE 傳到 Mac 小程式，本機 Whisper 轉文字後貼進目前的輸入框。

和 `BT DICT`（A 方案，只送聽寫快捷鍵、用 Mac 麥克風）是兩回事。選單裡用到這條串流的有兩項：

- **WHISPER**：邊錄邊傳，文字貼到游標處。需要 btmic 在線。
- **NOTE**：離線也能錄，錄音先存進 Stick 的收件匣；回到 NOTE 畫面且 btmic 在線時自動補傳，文字存進 `~/btmic-inbox.md`，不貼上。

## 流程

```
按住前鍵 ─▶ Stick 開始錄音（螢幕紅色）─▶ ADPCM 分段經 BLE 通知
放開前鍵 ─▶ Stick 送 end 幀 ─▶ Mac 小程式組成 WAV ─▶ mlx_whisper ─▶ 文字
                                                     └▶ 剪貼簿 + Cmd+V 貼上（可選送 Return）
```

## 為什麼用 IMA ADPCM

- BLE 實際頻寬有限。16 kHz、16 bit PCM 是 256 kbps，太高。
- IMA ADPCM 4 bit，16 kHz 為 64 kbps，兩端實作都只要幾十行，不用額外函式庫。
- 語音品質對 Whisper 足夠；比 8 kHz μ-law 好。
- 日後可換 Opus，協議保留 `codec` 欄位。

## GATT

自訂服務，和既有 HID 服務並存（HID 使用 `0x1812`，互不影響）。

| 項目 | UUID | 屬性 |
|---|---|---|
| Service | `5e3b0000-8a7c-4f1e-9b2d-7c4a1f0e6d10` | |
| `audio_tx` | `5e3b0001-8a7c-4f1e-9b2d-7c4a1f0e6d10` | notify，需加密 |
| `ctrl_rx` | `5e3b0002-8a7c-4f1e-9b2d-7c4a1f0e6d10` | write without response，需加密 |

所有特徵都要求加密連線，沿用 HID 已有的綁定（`SM_LVL=2`）。初稿的 `state_tx` 沒有實作，也用不到。

服務在 `components/esp_hid/src/nimble_hidd.c` 的 `nimble_hid_start_gatts()` 裡、HID 服務之後註冊（弱符號 `vox_audio_svc_init`），與 HID 並存。

## 音訊幀（`audio_tx`，小端序）

| 位移 | 大小 | 欄位 |
|---|---|---|
| 0 | 1 | `ver` = 1 |
| 1 | 1 | `type`：1 = 音訊，2 = 結束，3 = 開始 |
| 2 | 2 | `session`：每次錄音遞增 |
| 4 | 2 | `seq`：幀序號，從 0 起 |
| 6 | 1 | `codec`：1 = IMA ADPCM 16 kHz 單聲道 |
| 7 | 1 | `flags`：bit0 = 離線（從收件匣補傳，Mac 存檔而不貼上） |
| 8 | 2 | `predictor`：int16，本幀起始預測值 |
| 10 | 1 | `index`：步階索引 0–88 |
| 11 | 1 | 保留 = 0 |
| 12 | 160 | 320 個樣本（20 ms），每位元組兩個，低四位元先 |

- 每幀 172 位元組，需要 ATT MTU ≥ 175（Mac 預設協商得到 185 以上）。
- 一秒 50 幀，約 69 kbps。
- 每幀自帶預測值與索引，掉幀不會讓後面全壞。
- `type` 2 的結束幀沒有 ADPCM 資料（長度 12）。

## 控制（`ctrl_rx`）

Mac 寫入 1 或 3 個位元組：`[狀態]` 或 `[狀態, 錄音編號低位, 錄音編號高位]`。

| 狀態 | 意義 |
|---|---|
| 1 | 轉寫中（BUSY） |
| 2 | 已完成（DONE）；補傳的空白或太短錄音也回這個，Stick 可丟棄 |
| 3 | 失敗（ERR，即時錄音的太短、靜音、轉寫失敗） |
| 5 | 心跳（PING），Mac 每 2 秒送一次 |

BUSY 最長維持 60 秒，DONE 與 ERR 維持 3 秒。

**心跳**：macOS 在 btmic 關掉後仍保留 Stick 的訂閱，光靠「已訂閱」無法知道 Mac 還在不在。Stick 要求 6 秒內收過心跳才算「連線可用」，否則 WHISPER 顯示 `NO LINK`、NOTE 改為離線錄音。

**補傳確認帶編號**：補傳的 DONE／ERR 必須帶該次錄音編號，編號相符 Stick 才刪除收件匣裡的那一筆；不符（例如即時錄音的結果）一律忽略，避免誤刪還沒送達的錄音。Mac 端對補傳錄音的轉寫出錯**不回覆**，Stick 等不到確認就保留，之後重試。

Stick 畫面：`NO LINK`（未訂閱／未加密／MTU 不足／無心跳，NOTE 顯示為橘色 `READY`）、`READY`、`REC`、`BUSY`、`DONE`、`ERR`、`SYNC`（補傳中）、`FULL`（收件匣滿）。NOTE 畫面另顯示 `N PENDING`。

結束幀會連送 3 次，因為通知可能掉；Mac 端也有 1.5 秒無資料的逾時保險。單次即時錄音上限 60 秒；離線錄音每筆上限 30 秒。

## 離線收件匣（NOTE）

- 使用自訂分區 `inbox`（`partitions.csv`，0x190000 起 3 MB），分成 12 個槽，每槽 256 KB、最長 30 秒。Stick 內建 8 MB flash，原本的應用分區 0x177000 仍有一半空間。
- 槽的標頭用「清除、使用中、完成」三個旗標字依序寫入，中途斷電的槽不會被當成有效錄音；錄音內容為 164 位元組一幀（預測值、索引、160 位元組 ADPCM）。
- 刪除先抹標頭，保證刪到一半不會再被當成待傳。抹除一次一個磁區，且只在選單或 NOTE 畫面閒置時做（抹除會讓 CPU 停約 45 毫秒）。
- 補傳以約 1.3 倍即時速度送出（每幀間隔 15 毫秒），每幀送失敗會一直重試直到連線斷掉；失敗後等 5 秒才重試，避免風暴。
- 補傳只在 NOTE 畫面進行；離開畫面時中止，錄音保留。
- 要更新分區表用 `tools/flash_interactive.sh menu-pt`（寫 0x8000 與 0x10000，保留 NVS 配對）；不要用只寫 0x10000 的 `menu-app`。

## 隱私與安全

- 麥克風**只在按住前鍵時錄音**，螢幕紅色；放開即停，藍牙不傳其他時間的音訊。
- 全程本機：Whisper 在 Mac 上跑，沒有網路請求，沒有雲端辨識。
- 連線必須加密綁定；沒有加密的連線無法訂閱 `audio_tx`。
- Mac 小程式不開任何網路埠。
- **只信任 macOS 已配對並連線的裝置**，並把第一次連上的 UUID 記在 `~/.btmic-device`（權限 600），之後只認這個 UUID；沒有掃描備援，所以偽造 `StickS3` 廣播連不上。重新配對後 UUID 變了，刪掉這個檔案即可重新綁定。
- 沒有對音訊幀做簽章：金鑰仍要靠同一條配對通道交換，信任基礎不變，卻讓協議複雜很多，所以不做。
- 預設只貼上，不按 Return；要自動送出需設環境變數 `BTMIC_ENTER=1`。
- 貼上需要「輔助使用」權限；沒授權時只複製到剪貼簿，不貼。
- 暫存 WAV 轉譯完立即移到垃圾桶。
- NOTE 的離線錄音以**未加密**的 ADPCM 存在 Stick 的 flash，補傳成功後才抹除；Stick 遺失時裡面的未傳錄音可被讀出。

## 實測結果與坑

1. **新增服務後 macOS 的服務快取**：用完整映像刷機（清掉 Stick 配對），Mac 也忘記裝置再重新配對，一次就成功。
2. **CoreBluetooth 看不到 HID 服務**：`retrieveConnectedPeripherals(withServices: [0x1812])` 回傳空，但用自訂服務 UUID 查得到已連線的 Stick（`btmic probe` 可重現）。所以接收端查自訂服務。
3. **隱私權（TCC）**：直接從終端機執行會因為缺少藍牙使用說明而被系統中止。所以包成 `out/btmic.app`（含 `Info.plist`），以 `open` 啟動，權限屬於 app 本身。藍牙與輔助使用都要對這個 app 授權；重新編譯後若失效，到系統設定移除再加入。
4. **頻寬**：即時錄音 3 到 4 秒與離線補傳 8.4 秒、3.2 秒的錄音丟幀皆為 0；30 秒以上與遠距離尚未測。補傳最初丟了約兩成幀，原因是送失敗 4 次就放棄，現在改為持續重試。
5. **延遲**：放開到文字出現約 3 到 4 秒，主要是 `whisper-medium` 轉寫時間。
6. **辨識**：中文含數字（「心跳每分鐘 120 下」）正確；夾英文的獸醫術語尚未測，之後再調提示詞。

7. **FreeRTOS 時鐘 100 Hz**：`pdMS_TO_TICKS(5)` 等於 0，`vTaskDelay` 變成空轉，優先權較高的補傳工作會餓死畫面工作，造成畫面畫到一半停住、按鍵似乎沒反應。短延遲至少用 1 個 tick；畫面工作優先權設為 6，高於按鍵與 btmic（5）。
8. **畫面與按鍵工作不要碰 NimBLE 主機鎖**：連線狀態由錄音工作定期更新到快取，其他工作只讀快取。
9. **配對碼畫面旗標**必須由畫面工作統一清除，否則進入沒有清除邏輯的畫面後，狀態列和熄屏會永久失效。
10. **診斷**：USB 是複合裝置，沒有序列埠記錄。NOTE 畫面底部小字 `S原因-次數 R錯誤碼`（原因：1 讀取失敗、2 送出失敗、3 連線中斷、4 開始錄音、5 成功、6 等回覆逾時、7 離開 NOTE）。監控工作偵測到畫面、按鍵或錄音工作 6 秒沒有回報會自動重開機，開機後頂端紅字 `R8 C<畫面><按鍵><錄音三位>` 與 `M<停擺遮罩> <握 LCD 鎖的工作名>` 指出誰在哪裡停住。

## 使用

```
tools/btmic/build.sh        # 編譯並簽署 out/btmic.app
tools/btmic/run.sh          # 啟動接收（記錄：~/.btmic.log）
pkill -x btmic              # 停止
out/btmic.app/Contents/MacOS/btmic selftest <16k 單聲道 wav>   # 離線自測（不需 Stick）
```

補傳的離線錄音文字在 `~/btmic-inbox.md`（每筆附日期與時間）。

環境變數：`BTMIC_LANG`（預設 `zh`）、`BTMIC_MODEL`（預設 `mlx-community/whisper-medium`）、`BTMIC_ENTER=1`。
